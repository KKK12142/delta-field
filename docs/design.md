# Delta Field 기획

교사와 대화하며 정한 내용을 적는다. 정하지 않은 것은 맨 아래에 모은다.

## 대상
- 중1·중2 영재수업 학생
- 고1~고3 통합과학, 물리학, 역학과 에너지, 전자기와 양자 수강 학생

## 수업 형태
- 방탈출: 각 실에서 단서를 찾고, 퀴즈를 풀고, 아이템을 얻어 탈출한다.
- 골든벨: 교사가 문제를 넘기면 모든 학생이 같은 문제를 동시에 푼다.
- 퀘스트: 임무를 받고 수행한다.
- 진행은 개인 단위로 한다.

## 화면
- 탑다운 시점: 바닥은 위에서 보고, 벽과 사물은 앞면이 보인다. 처음의 아이소메트릭 시점에서 바꿨다(2026-11-11).
  까닭: 움직임·충돌·맵 짜기·조이스틱이 단순하고, 생성 그림을 맞추기 쉽고, CCTV 모드에서 전체를 보기 쉽고, Unity 2D 타일맵으로 옮기기 쉽다.
- 방향키·조이스틱을 민 방향대로 화면에서 움직인다.

## 장소
- 교실, 실험실, 복도, 야외
- 장소와 자료(단서, 퀴즈, 아이템)는 교사가 화면에서 배치하지 않고, 맵을 만들 때 미리 배치한다.

## 접속
- 한 수업에 최대 35명이 들어온다.
- 노트북과 태블릿으로 접속하고, 학교 교실의 와이파이(AP)를 쓴다.
- 학생은 닉네임을 직접 입력한다.
- 태블릿에서는 가상 조이스틱으로 움직인다. 노트북은 방향키와 WASD를 쓴다.
  - 교사 요청(2026-11-11): 조이스틱이 왼쪽 아래 구석에 너무 붙어 있었다. 화면 왼쪽 절반(높이 전체)의 어디든 누르면
    그 자리에 조이스틱이 나타나고, 끌면 움직이고, 떼면 사라진다. 화면 끝을 누르면 바탕이 화면 안에 들어오게 가운데를 당긴다.
  - 살펴보기 단추(오른쪽 아래)는 조이스틱을 쥔 채 다른 손가락으로 누를 수 있다. 터치는 손가락을 대는 순간 누른 것으로 친다.
  - 선생님의 CCTV 모드에서는 조이스틱 영역을 감춰 지도 위 학생을 누를 수 있다.

## 교사 화면
- 학생들과 함께 돌아다니며 볼 수 있다.
- CCTV 모드: 전체 학생의 위치와 하고 있는 활동을 본다. 학생 한 명을 누르면 그 학생을 따라가며 본다.

## 만드는 순서
1. 서버 없이 혼자 하는 방탈출 한 판. 닉네임 입력 → 이동 → 단서 찾기 → 퀴즈 → 아이템 → 문 열고 탈출.
   그림은 단순한 도형으로 하고 흐름부터 만든다.
2. 서버를 붙여 최대 35명이 함께 들어오게 한다. CCTV 모드와 골든벨을 만든다.

## 1단계 진행(2026-11-11)
- 교실 방탈출 한 판을 단순한 도형으로 만들었다. 방 내용은 src/data/classroom.json에 있다.
- 흐름: 칠판(단서) → 교탁(퀴즈) → 사물함 열쇠 → 사물함(퀴즈) → 교실 문 열쇠 → 문(퀴즈) → 탈출.
- 퀴즈 세 개는 예시 문제다(화면에 "예시 문제" 표시). 교사가 바꿔 넣는다.
- 노트북: 방향키·WASD, 스페이스바(또는 E)로 살펴보기. 태블릿: 왼쪽 아래 조이스틱, 오른쪽 아래 살펴보기 단추.
- 아래는 교사가 정하지 않아 우선 이렇게 해 둔 것이다.
  - 틀린 답을 고르면 그 보기만 막고 다시 고르게 한다. 벌점이나 횟수 제한은 없다.
  - 열쇠는 쓴 뒤에도 가진 물건에 남는다.
  - 걸린 시간은 탈출한 뒤에만 보여 준다.
  - 닉네임은 12자까지 받는다.

## 2단계 결정(2026-11-11)
- 서버 프로그램: Colyseus. Unity용 연결 도구가 있어 나중에 Unity 앱도 같은 서버에 붙일 수 있다.
- 학생은 선생님이 수업마다 만드는 방 코드와 닉네임을 넣고 들어온다.
- 선생님은 비밀번호로 구분한다. 비밀번호는 서버의 .env에만 두고 저장소에 넣지 않는다.
- 실제 수업 때 서버는 교사의 맥에 둔다. 학생 기기와 맥이 같은 학교 와이파이에 있으면 인터넷 없이도 접속할 수 있다.
  학교 와이파이가 기기끼리의 연결을 막는지(클라이언트 격리)는 학교에서 확인해야 한다.
- 만드는 순서: ① 서로 움직이는 모습 보기 → ② CCTV 모드 → ③ 골든벨(규칙은 ③ 전에 정한다)

## 2단계 ① 진행(2026-11-11)
- 선생님: 첫 화면에서 "선생님으로 들어가기" → 비밀번호 → 새 방(4자리 코드)을 만든다. 같은 코드와 비밀번호로 다시 들어올 수 있다.
- 학생: 닉네임과 방 코드로 들어온다. 같은 방 안에서 닉네임이 겹치면 들어오지 못한다.
- 같은 교실에 있는 다른 사람이 보인다(나: 파랑, 다른 학생: 연한 파랑, 선생님: 주황). 방탈출 진행(아이템, 퀴즈)은 각자 따로다.
- 선생님 화면 오른쪽 위에 방 코드와 접속한 학생 수가 보인다.
- 와이파이가 잠깐 끊겨도 20초 안에 돌아오면 같은 자리로 다시 붙는다. 끝내 끊기면 처음 화면으로 돌아가는 안내가 뜬다.
- 시작 위치는 여럿이 겹치지 않게 시작점 둘레(1.5칸 안)에 흩어 놓는다.
- 맥에서 수업용으로 켜기: 저장소를 받고 .env에 선생님 비밀번호를 넣은 뒤 pnpm install, pnpm start. 화면에 학생 접속 주소가 나온다.

## 2단계 ② 진행: CCTV 모드(2026-11-11)
- 교사가 정한 것
  - 학생마다 보일 것: 지금 하는 일, 진행 정도(가진 물건, 마친 사물 수, 탈출 여부). 틀린 답 수와 걸린 시간은 넣지 않는다.
  - 전체 보기: 교실 지도는 그대로 두고 오른쪽에 학생 목록을 둔다.
  - 학생을 누르면 확대해서 따라가고, 옆 창에 그 학생의 정보를 보인다. 학생이 연 퀴즈 창은 선생님 화면에 띄우지 않는다.
- 켜고 끄기: 선생님 화면 오른쪽 위의 "CCTV 보기" 단추, CCTV 창의 "CCTV 끄기" 단추.
- 목록: 닉네임 순. 학생마다 닉네임, 진행(예: 진행 2/4), 지금 하는 일을 보인다.
  지금 하는 일은 돌아다니는 중, ○○ 살펴보는 중, ○○ 퀴즈 푸는 중, 탈출 완료, 연결 끊김 가운데 하나다.
- 따라가기: 목록이나 지도의 학생을 누른다. 정보 창에 지금 하는 일, 진행, 가진 물건이 보인다. Esc나 "전체 보기"로 돌아간다.
- 학생 화면이 진행 상태를 서버에 보내고, 서버는 방 데이터에 있는 사물·아이템 id만 받는다.
- 아래는 교사가 정하지 않아 우선 이렇게 해 둔 것이다.
  - CCTV 모드인 동안 선생님은 움직이지 않는다. 선생님 아바타는 그 자리에 남아 학생에게 보인다.
  - 지도의 아바타 위 표시는 돌아다니는 중이 아닐 때만 띄운다(35명이 모여도 덜 겹치게).
  - 진행은 살펴볼 수 있는 사물(칠판, 교탁, 사물함, 문) 가운데 마친 수다. 문은 탈출하면 마친 것으로 친다.
  - 와이파이가 끊겨 다시 붙기를 기다리는 학생은 "연결 끊김"으로 보인다.

## 2단계 ③ 진행: 골든벨(2026-11-11)
- 교사가 정한 규칙
  - 목숨은 3개다. 틀리면 하나씩 잃고, 다 잃으면 탈락한다.
  - 탈락한 학생도 계속 문제를 푼다. 탈락한 뒤 3문제를 맞히면(연속이 아니어도 된다) 목숨 1개로 다시 살아난다.
  - 점수는 맞힌 문제 수다. 탈락해 있는 동안 맞힌 문제는 점수에 넣지 않고, 다시 살아난 뒤 맞힌 문제는 넣는다.
  - 제한 시간은 문제마다 정한다. 문제는 OX와 객관식이 섞인다.
  - 문제는 YAML 파일로 만든다(goldenbell/ 폴더, 형식은 goldenbell/example.yaml).
  - 골든벨을 시작하면 모두 골든벨 맵으로 옮겨 간다. 답은 맵의 답 구역(OX는 O·X, 객관식은 1~4)으로 걸어가서 고르고,
    시간이 끝날 때 서 있는 구역이 답이다.
- 진행: 선생님이 교실에서 "골든벨 시작" → 문제 파일 고르기 → 모두 골든벨 맵으로 옮김 → "첫 문제" →
  시간이 끝나면 서버가 채점하고 정답 공개 → "다음 문제" … → 마지막 문제 뒤 "결과 보기"(순위) → "골든벨 끝내기"로 모두 교실로 돌아간다.
- 서버만 문제 파일을 읽고 채점한다. 정답은 공개할 때 학생 화면에 보낸다.
- 교사 요청(2026-11-11): 문제가 시작되면 학생 화면에서는 다른 학생이 점점 투명해지다가 사라져 나만 보인다(다른 학생을 따라 움직이지 못하게).
  목숨은 학생마다 머리 위에 하트(♥♥♡)로 보인다. 하트는 바탕 없이 흰 테두리를 둘러 띄운다.
  탈락하면 해골 3개(💀💀💀)로 바뀌고, 맞힐 때마다 하나씩 없어져 다 없어지면 다시 살아난다(♥♡♡).
  - 우선 이렇게 해 둔 것: 2초 동안 흐려진다(src/theme.ts의 motion.gbFadeMs). 정답을 공개하면 모두 다시 보인다. 선생님 화면에서는 늘 모두 보인다.
- 형식이 틀린 문제 파일은 고르는 목록에 까닭(몇 번 문제의 무엇이 틀렸는지)과 함께 보이고 고를 수 없다.
- 아래는 교사가 정하지 않아 우선 이렇게 해 둔 것이다.
  - 시간이 끝날 때 어느 구역에도 서 있지 않으면 틀린 것으로 센다.
  - 골든벨이 끝나면 학생은 교실의 원래 자리로 돌아가고 방탈출 진행은 그대로다.
  - 골든벨 중에 들어온 학생은 골든벨 맵에서 목숨 3개로 시작한다.
  - 학생 화면에는 순위를 위쪽 10명까지, 선생님 창에는 모두 보인다. 같은 점수는 같은 등수다.
  - 탈락한 학생의 아바타는 흐리게 보인다.
  - 선생님 문제 파일은 정답이 들어 있어 공개 저장소에 올리지 않는다(.gitignore). 예시 파일만 올린다.

## 35명 접속 시험(2026-11-11)
- 집 데스크탑(WSL)에서 했다. 가짜 학생(봇) 34명, 크롬 학생 1명, 크롬 선생님 1명이 들어왔다. 봇은 쉬지 않고 움직여 실제 수업보다 무겁다.
  모두 같은 컴퓨터 안이라 와이파이를 거치지 않았다. 다시 할 때는 pnpm loadtest를 쓴다.
- 결과
  - 34명이 동시에 0.1초 안에 들어왔다. 선생님 화면에 35명, CCTV 목록에 35줄이 보였다.
  - 서버 CPU는 코어 1개의 3%(골든벨 2%), 메모리는 약 110 MB다.
  - 기기 1대가 받는 데이터는 초당 6.4 KB(0.05 Mbps)이고, 36대를 합하면 1.9 Mbps다.
  - 골든벨 7문제 모두 35명을 채점했고, 순위 35줄이 나왔으며, 끝낸 뒤 모두 교실로 돌아왔다.
  - 화면 빠르기(그래픽 카드 없이 그리는 헤드리스 크롬이라 참고용): 2명일 때 60fps, 35명일 때 45fps.
  - 35명이 모이면 지도에서 닉네임과 CCTV 표시가 많이 겹친다.
- 교사가 실제 기기에서 확인했다: 집 데스크탑 공유 서버에 봇 34명을 넣고 윈도우 크롬·태블릿으로 교실·CCTV·골든벨을 보았고,
  수업용 맥에서 pnpm start로 켜고 pnpm bots로 봇을 넣어 확인을 마쳤다.
- 남은 확인: 학교 와이파이에서 학생 기기가 맥에 닿는지.

## 그림 결정(2026-11-11)
- 도트(픽셀) 그림. 화면의 한 칸 48px = 도트 16개 × 3배. 규격과 만드는 과정은 docs/art.md.
- 학생은 첫 화면에서 캐릭터 6~8가지 중 하나를 고른다. 나중에 Delta Science 업적 포인트로 꾸미기를 더할 수 있게 몸·머리·옷 겹을 생각해 둔다.
- 그림 생성은 BAZE(게이트웨이)에 API 키로 GPT 이미지 생성을 부른다. 키는 저장소 밖 ~/.config/delta-field/baze.env에 교사가 넣는다.
- 맵은 교실-복도-실험실-운동장을 하나로 이은 학교 맵으로 바꾼다(화면이 내 캐릭터를 따라간다). 맵 담당이 만드는 중.
- 여러 세션으로 나눠 일한다: 대장(교사와 대화), 맵 담당, 그림 담당(CLAUDE.md "여러 세션으로 일할 때").

## 앞으로의 방향
- 나중에 Unity(CLI)로 옮겨 앱으로 만들 수 있다. 단서, 퀴즈, 아이템 같은 내용은 코드와 떨어진 데이터 파일(JSON)에 둔다.
- Delta Science(deltascience.kr)에서 제출한 문항에 따라 업적을 주고, 업적 포인트로 Delta Field에서 캐릭터 꾸미기 등을 한다.
  두 프로젝트가 같은 학생을 알아보는 방법이 필요하다. 2단계 뒤에 정한다.

## 개발 중 확인
- 맥과 태블릿에서는 Tailscale 망 안에서만 보이는 주소로 개발 서버를 연다. pnpm share(켜기), pnpm share:off(끄기), pnpm share:status(상태).
- 공유 중인 서버(5173, 2567)를 그대로 둔 채 확인용 서버를 따로 켤 때는 DF_WEB_PORT, DF_PORT로 포트를 바꾼다(README 참고).
