> **Author**: 교사 + 대장
> **Last Updated**: 2026-11-22(밤, 운동장)

## Summary

지금 2D로 돌아가는 골든벨(OX·객관식·단답형, 목숨 3개, 탈락 뒤 부활)을 규칙은 그대로 두고 three.js 3D 경기장으로 옮긴다.
학생은 고정 시점 카메라로 내려다보는 경기장에서 자기 동물 캐릭터를 몰아 답 구역에 서고, 시간이 끝날 때 선 구역이 답이 된다.

> **Quick reference** — Layer: `Feature` · Priority: `Vertical Slice` · Key deps: `서버 골든벨 규칙(shared/goldenbell.ts, server/ClassRoom.ts), 3D 시제품(src/three), 문제 파일(goldenbell/*.yaml)`

## Overview

선생님이 "강당으로 모으기"로 모두를 골든벨 경기장으로 옮기고 문제를 낸다. 3D 화면에서도 진행 순서, 채점, 목숨·부활·점수 규칙은
2D와 똑같고(서버가 채점), 바뀌는 것은 보이는 모습이다: 바닥에 크게 칠한 답 구역, 머리 위 하트, 정답 공개 때의 구역 빛과 캐릭터 동작,
탈락한 학생의 흐린 모습. 문제 카드·내 상태·단답형 입력 칸·순위 같은 글은 지금처럼 HTML로 화면 위에 얹는다.
2026-11-22 교사 결정: 2D는 더 쓰지 않는다. 모든 화면의 기본을 3D로 바꾼다(2D 코드는 지우지 않고 `?view=2d`로만 연다).

## Player Fantasy

- 학생: "운동장에서 친구들과 우르르 답 칸으로 달려가는" 골든벨. 내 동물이 정답 칸에서 펄쩍 뛰고, 틀리면 쓰러졌다가 다시 살아나 돌아오는 재미.
  문제를 푸는 동안에는 남을 따라가지 않고 스스로 고른다(다른 학생이 흐려짐).
- 선생님: 한눈에 경기장 전체와 누가 어디 섰는지 보이고, 정답 공개 순간이 교실 화면(프로젝터)에서도 잘 보인다.

## Detailed Design

### Core Rules

규칙은 docs/design.md "2단계 ③ 진행: 골든벨"과 "골든벨 단답형"을 그대로 따른다(서버가 정하는 것). 요약:
1. 목숨 3개(보너스 미션·미니게임 하트로 최대 5). 틀리면 1개 잃고, 0이면 탈락.
2. 탈락한 학생도 계속 푼다. 탈락 뒤 2문제를 맞히면 목숨 1개로 부활.
3. 점수 = 맞힌 문제 수(탈락 중에 맞힌 것은 빼고, 부활 뒤는 셈). 넌센스 문제는 점수에 넣지 않고 하트 +1 또는 부활 1개로 셈.
4. OX·객관식: 시간이 끝날 때 서 있는 답 구역이 답. 어느 구역에도 없으면 틀림.
5. 단답형: 문제 카드 안 입력 칸에 써서 낸다(마지막에 낸 답으로 채점, 걷기는 계속 가능).
6. 문제를 푸는 동안 학생 화면에서는 다른 학생이 2초(theme gbFadeMs) 동안 흐려지다 사라진다. 정답 공개 때 다시 보인다. 선생님 화면은 늘 모두 보인다.

3D에서 새로 정하는 것(보이는 모습만, 서버 규칙은 바꾸지 않음):
7. 경기장(2026-11-22 밤 교사 요청으로 고침): 넓은 잔디 운동장(src/data/goldenbell.json 44×28칸, 서버도 같은 파일). OXplayground처럼 둘레 울타리·트랙, 가운데 출발 자리,
   O칸(왼쪽)·X칸(오른쪽)이 각 14×20칸, 객관식 1~4는 같은 넓이를 2×2로 나눔(각 14×9칸). 가운데 8칸과 1·3 / 2·4 사이 2칸은 어느 구역도 아닌 통로다.
   칸 좌표를 그대로 3D 바닥으로 옮긴다(한 칸 = 1). 답 구역은 바닥에 크게 칠한 판(OX: 왼쪽 O 파랑·오른쪽 X 빨강, 객관식 1~4: 2D와 같은 자리·색)과 구역 이름 큰 글자.
   구역 판·글자·보기 글은 캐릭터보다 아래(바닥 바로 위)에 깐다. 캐릭터·이름표·하트가 늘 위에 보인다(교사 요청: 발판이 캐릭터를 가리지 않게).
   자세한 좌표와 꾸밈은 design/quick-specs/goldenbell-playground.md.
8. 문제 단계별 구역 모습: 대기(흐린 판) → 문제(또렷한 판, 지금 문제 종류의 구역만) → 마감(판 테두리가 닫히는 효과) → 정답 공개(정답 구역 빛남, 나머지 어두워짐).
9. 머리 위 하트: 이름표 아래에 하트 줄(♥♥♡). 탈락이면 해골(💀💀, 부활까지 남은 수). 2D와 같은 뜻.
10. 정답 공개 동작: 맞힌 학생은 jump, 틀린 학생은 그냥 서 있기(idle, 2026-11-22 교사 결정), 탈락한 학생은 경기장 안에서 반투명으로 계속 푼다(교사 결정).
11. 카메라: 학생은 지금 3D 시제품처럼 나를 따라가는 고정 시점. 문제 카드가 위를 가리므로 따라가는 범위를 카드 높이만큼 내려 맨 윗줄 구역도 보이게 한다(2D와 같은 원칙).
    선생님은 경기장 전체가 한 화면에 들어오는 고정 시점(프로젝터용).

### States and Transitions

서버 상태 `gb.phase`를 그대로 따른다(새 상태를 만들지 않는다).

| 상태 | 3D 화면 |
|---|---|
| 모으는 중(강당으로 옮김) | 경기장에 들어오며 대기 판, 문제 카드 자리에 안내 |
| question(문제 푸는 중) | 해당 종류 구역만 또렷, 남은 시간, 다른 학생 흐려짐 |
| 마감(시간 끝, 채점 중) | 구역 테두리 닫힘 효과, 움직임은 서버 규칙대로 |
| reveal(정답 공개) | 정답 구역 빛남, 맞힘·틀림 동작, 하트 바뀜, 모두 다시 보임, 해설 |
| result(결과 보기) | 시상대·순위(HTML), 1~3등 캐릭터 jump |
| 끝(골든벨 끝내기) | 학교 맵으로 돌아감(3D 학교 맵 또는 2D, 지금 규칙대로) |

### Interactions with Other Systems

- 서버(server/ClassRoom.ts, shared/goldenbell.ts): 바꾸지 않는다. 3D는 같은 상태(schema)를 읽는다.
- 3D 시제품(src/three): 캐릭터·카메라·보간·moveSeq를 그대로 쓰고 골든벨 경기장 그리기를 더한다.
- HTML 안내(src/ui, src/game/goldenbell.ts): 문제 카드·내 상태·단답형 칸·순위·선생님 창을 그대로 얹는다. 휴대폰 규칙(카드 접기 등)도 그대로.
- 캐릭터 모델: 지금은 cat-astra 하나(임시). 최종 동물 모델은 마지막에 Tripo + Blender 리깅(docs/design.md).

## Formulas

새 공식은 없다. 점수·목숨·부활은 shared/goldenbell.ts의 값(GB_LIVES 3, GB_MAX_LIVES 5, GB_REVIVE_CORRECT 2, GB_REVIVE_LIVES 1)을 그대로 쓴다.
화면 쪽 계산:
- 구역 판 위치: 3D x = col + w/2, z = row + h/2(칸 좌표 그대로, 한 칸 = 1). 판 크기 w × h.
- 흐려짐: 투명도 = 1 − 지난 시간 / gbFadeMs(0 미만은 0, 그 뒤 감춤).

## Edge Cases

- 구역 경계에 걸쳐 선 학생: 서버 판정(발 위치의 칸)을 그대로 따른다. 화면은 서버가 준 자리를 보인다(내 화면만 앞서 가 보이는 차이가 있을 수 있음).
- 문제 중에 들어온 학생: 지금 규칙대로 목숨 3개로 시작, 3D에서도 경기장 시작 자리에 선다.
- 연결이 끊겼다 이어 하기: 지금 규칙대로 목숨·점수를 이어 받고 서버 자리에 선다.
- 35명이 한 구역에 몰림: 캐릭터가 겹쳐도 판정은 서버. 이름표가 겹쳐 읽기 어려우면 학생 화면은 내 이름표만 크게(조정값).
- 느린 기기(fps 낮음): 픽셀 비율 상한을 낮추고 효과(빛남·흐려짐)를 단순하게 하는 설정을 둔다.
- 단답형에서 화면 키보드: 2D처럼 터치 기기는 칸을 눌러야 쓴다(지도 가림 방지).

## Dependencies

- 서버 골든벨 규칙과 문제 파일(바꾸지 않음)
- 3D 시제품 ①(완료), 고양이 임시 모델(완료)
- HTML 골든벨 안내(src/ui, 그대로)

## Tuning Knobs

모두 src/theme.ts(three 묶음)에 둔다.
- 구역 판 색·투명도(대기/문제/정답/오답), 구역 글자 크기
- 하트 크기·높이, 이름표 높이
- 정답 공개 효과 길이(빛남·동작), gbFadeMs(지금 2000)
- 학생 카메라: 보이는 칸 수(theme.three.gbStudentTiles, 지금 14), 내려다보는 각, 카드 높이만큼 내리는 양
- 운동장 모습(theme.playground): 잔디·트랙·선 색, 나무·건물 크기, 구역 이름 그림 배율(labelScale 2)
- 선생님 카메라: 경기장 전체 여백
- 느린 기기 설정: 픽셀 비율 상한, 효과 켜기·끄기

## Visual/Audio Requirements

- 운동장은 코드로 만든 단순한 모양: 잔디 줄무늬·흰 선·트랙(캔버스 판 하나), 낮은 울타리, 울타리 밖 나무·학교 건물 뒷배경(InstancedMesh). 꾸밈 그리기는 5번 안팎.
  더 꾸미기(CC0 묶음 소품)는 나중에.
- 소리(효과음)는 이 문서 범위 밖. OXplayground처럼 합성 효과음은 따로 기획한다.

## Game Feel

- 문제가 시작되면 구역이 "켜지는" 느낌, 남은 3초에 시간 글자가 커지고 깜박임(HTML 카드).
- 정답 공개 순간이 가장 큰 보상: 정답 구역이 밝아지고 맞힌 캐릭터가 동시에 뛰어오름.

## UI Requirements

지금의 HTML 골든벨 안내를 그대로 쓴다(문제 카드 2×2 보기, 휴대폰 12px·카드 접기, 순위 접기, 선생님 창). 3D에 맞춰 바꾸는 것은 없다.

## Acceptance Criteria

1. `?view=3d`로 들어간 학생이 "강당으로 모으기" 뒤 3D 경기장에 서고, OX·객관식·단답형 문제를 각각 한 번 이상 풀 수 있다(pnpm playtest 같은 자동 확인으로 3D 경로도 한 판).
2. 서버 채점 결과(목숨·점수·탈락·부활)가 2D로 들어간 학생과 같은 판에서 똑같다(2D 학생 1명 + 3D 학생 1명 동시 시험).
3. 정답 공개 때 정답 구역이 빛나고, 맞힌 학생 캐릭터가 jump한다(캡처를 production/qa/evidence/에 남김).
4. 문제 중 학생 화면에서 다른 학생이 gbFadeMs 안에 사라지고, 정답 공개 때 다시 보인다(캡처).
5. 머리 위 하트·해골이 서버 목숨과 맞는다(캡처).
6. 봇 35명 골든벨 중 3D 학생 화면 fps를 재서 2D와 견준다(헤드리스 참고값, 실제 태블릿 값은 교사 확인).
7. 주소에 아무것도 붙이지 않으면 3D로 열린다. `?view=2d`로 연 2D 골든벨도 그대로 동작한다(pnpm playtest를 ?view=2d로 돌려 통과).

## Decisions(2026-11-22 교사)

1. 틀렸을 때 캐릭터 동작: 우선 그냥 서 있기.
2. 탈락한 학생: 경기장 안에서 흐리게 계속 푼다(응원석 없음).
3. 경기장 꾸미기: 틀을 다 잡은 뒤에.
4. 2D는 더 쓰지 않는다. 모든 화면의 기본을 3D로(2D는 ?view=2d로만, 코드는 남김).
